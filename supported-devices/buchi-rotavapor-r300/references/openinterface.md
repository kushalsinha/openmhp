# BUCHI R-300 OpenInterface: what this package uses

Sources, all published by Büchi:

- "BUCHI R-300 OpenInterface", OpenAPI 3 specification version 1.0.0, `R300_openinterface.yaml` in
  github.com/buchi-labortechnik-ag/openinterface_rotavapor (with `root_cert.crt` and a README on enabling
  the interface and its users).
- github.com/buchi-labortechnik-ag/openinterface_examples_python (MIT): `csv_recorder`, `stop_at_vaportemp`,
  `modbus_server` examples, which show the request shapes actually sent.
- developer.buchi.digital/rotavapor/openinterface/doc (rendered from the same YAML).

## Transport

| Item | Value |
|---|---|
| Base URL | `https://<host>/api/v1` (port 443, self-signed certificate; `root_cert.crt` verifies it) |
| Auth | HTTP basic; users `ro` (read) and `rw` (read/write); passwords generated by the interface |
| Enable | Settings > Rotavapor Open Interface on the I-300 Pro; restart; needs the VacuBox |
| Errors | 400 BadParameters, 401, 403, 405, 413, 415 (body not JSON), 500; `GET /info` 503 while starting |

## Endpoints used

| Purpose | Call |
|---|---|
| Identity, firmware, run counters | `GET /info` (`systemClass`, `systemName`, `controller{model, serial, firmware, runCounters}`) |
| Live values | `GET /process` |
| Setpoints, start/stop, valves, lift | `PUT /process` with a partial body (`{section: {field: value}}`; the README's example is `{"vacuum": {"set": 100}}`) |

Not used: `/settings`, `/messages`, `/health`, `/webhooks`.

## `/process` fields used

| Section.field | Access | Meaning here |
|---|---|---|
| `heating.set` (0..220 degC) / `heating.act` / `heating.running` | rw / ro / rw | bath setpoint, bath temperature, heater enabled |
| `cooling.set` (-10..25) / `cooling.act` / `cooling.running` | rw / ro / rw | chiller |
| `vacuum.set` (0..1300 mbar) / `vacuum.act` | rw / ro | pressure setpoint and reading |
| `vacuum.aerateValveOpen` | rw | vent valve; true vents to atmosphere |
| `vacuum.vaporTemp` | ro | vapour probe (degC) |
| `vacuum.running`, `vacuum.powerPercentAct` | ro | pump state |
| `rotation.set` (0..280) / `rotation.act` / `rotation.running` | rw / ro / rw | rotation |
| `lift.set` (0 or 220 mm; multipleOf 220) / `lift.act` / `lift.limit` | rw / ro / ro | 0 = up, 220 = down |
| `globalStatus.running` | rw | start/stop the whole process (`stop_at_vaportemp.py` stops with `{"globalStatus": {"running": false}}`) |
| `globalStatus.processTime`, `runId`, `onHold`, `foamActive`, `currentError`, `timeStamp` | ro | status |
| `program.type` | rw | Manual, Timer, Solvent, Method, AutoDest, CloudDest, Dry, Calibration, TightnessTest; this package leaves it at Manual |

## Unverified

- Whether `heating.running: true` alone starts the bath without `globalStatus.running`; this package sets both.
- Whether `aerateValveOpen: true` also stops the pump, or only opens the valve while the pump keeps
  running; the e-stop sets `globalStatus.running: false` first for that reason.
- Whether `cooling.set` is accepted on a unit without a chiller (the write may answer 400).
- The response body of `PUT /process` (the spec says the full Process object; the driver ignores it).
- The water-bath ceiling of 95 degC is Büchi's bath limit (`settings.heating.maxTemperature`), not an
  OpenInterface bound; the interface accepts up to 220.
